Brand directions before “FinEngine” becomes too generic

The default is now more distinctive, but the implementation stays easy to rename later because the brand lives in one JS config plus one CSS token.

Recommended default

FinKernel

Kernel signals a finance computation core. It feels technical, modular, and well matched to a library ecosystem rather than a consultancy brand.

Best for package familiesLess generic than FinEngine

FinLayer

Good if you want a middleware or orchestration position. Slightly softer than FinKernel and less calculation-centric.

Platform toneReadable for non-dev buyers

FinGrid

Suggests systems, data flows, and networked finance tooling. Strong for dashboards, settlement rails, and data products.

Systems feelGood visual metaphor

FinScope

Works well if the long-term angle is analytics, audit visibility, or financial observability rather than pure computation.

Audit signalExecutive-friendly

LedgerForge

Very memorable for ledger-heavy infrastructure, though more specific and less broad if you later move beyond core accounting rails.

High memorabilityNarrower category signal

FinEngine

Still credible, but it sounds broader and more common. It now stays as a reversible fallback instead of the default front brand.

Package system and library surface

The site now behaves more like live docs for a JavaScript fintech toolkit: tabs, filters, accordions, copy helpers, and a browser-side calculator are all wired with modular JavaScript.

Computation and reporting foundation

/core

validation kernel

Shared money types, rounding rules, ledger-safe validation, and deterministic domain contracts.

Without a hard validation core, lending, payment, and statement modules drift apart and audit explanations become weak.

/math

calculation engine

Amortization, XIRR, APR helpers, fee ladders, schedule generation, tax and payroll utilities.

npm install

/reporting

document outputs

Finance-oriented summaries, statement blocks, export schemas, and traceable audit-ready tables.

Prioritize consistency between on-screen previews and PDF or Excel export payloads, even before adding pro features.

Developer experience and product interface

/ui

micro-components

Repayment tables, payment cards, amount inputs, statement modules, and fintech-specific interface building blocks.

npm install

/react

framework adapter

Headless hooks and framework connectors so the core logic feels native inside a React application.

/docs-site

documentation shell

The website itself acts like a reusable documentation shell with counters, tabs, reveal motion, and calculator modules.

Payment rails and ledger adjacency

/pay

payment utilities

Merchant payload helpers, QR structures, display formatting, and interoperability-ready payment utilities.

/ledger

journal helpers

Double-entry helpers, account mapping conventions, and reconciliation-first ledger structures.

/signals

event intelligence

Threshold checks and event-level flags that can grow into a future risk-monitoring or compliance layer.
